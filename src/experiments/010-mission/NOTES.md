# 010 · Mission Control —— 设计笔记

> **这个实验在回答什么**

同时派五个 Agent 出去干活，界面长什么样？把五个聊天窗口并排放不算答案 ——
那是把一个问题复制五遍。控制塔的答案是：主角不是对话，是**状态**。

> **怎么表达**

- **每行一个 agent**：名字是 worktree 分支名（等宽小字），任务一句话。
- **telemetry 一直活着**：最新活动一行等宽小字在滚，进度在爬，
  ACU 成本两位小数在跳，elapsed 计时在走。就算剧本一拍不发，集群也在呼吸。
- **确认门**：被依赖冲突卡住的 agent 整行泛琥珀色，展开是问题和两个选项。
  拍板是这页唯一的「交互高潮」，所以只给琥珀一种颜色。
- **Inbox**：干完一件事自己落一张回执（PR 已开 / 测试通过 / 需要确认），
  点回执跳到对应 agent。用户不需要盯着看 —— 这是异步协作的礼貌。

> **视觉立场**

深色、发丝分割线、等宽小字、几乎没有圆角。这是控制台，不是聊天软件。
蓝色给「在跑」，绿色给「跑完」，琥珀只给「等你拍板」。

> **灵感来源**

Cursor 2.0 的并行 agent 面板、Google Antigravity 的 Manager Surface、
Devin 的 Agent Command Center。感谢这几家把「多 agent 并行」做成了主流范式。

> **交互清单**

暂停/恢复任意 agent · 琥珀门拍板（A/B） · 展开看 telemetry ·
点回执跳转 · 底部虚线框现场派一个新 agent。
