# A1 · The Brief —— 设计笔记

> **这个实验在回答什么**
> 如果界面的主角是「这份委托」，而不是聊天记录，会怎么样？
>
> 这是第二阶段的第一个实验。前面六个问的是「Agent 干活的过程还能怎么表达」，
> 从 A1 开始问的是：**「如果这是一个真正给人使用的 Agent UI，它还能长什么样？」**

---

## 一、核心问题

**用户交给 Agent 的，从来不是一句话，是一件事。**

现在所有 Agent UI 的输入都是一个文本框。你把这件事：

> 做一份 Q3 复盘，按 GMV 口径，用 analytics 的数据，下周要，别超过 1500 字

压成一行字发出去，然后 Agent 开始**猜**：猜哪三条产品线、猜含税不含税、猜文档还是 PPT。猜错了你再说一遍，它再猜一遍。

**聊天框把一次「委托」降维成了一次「发言」。** 发言是一次性的、无状态的、事后无法核对的。

真正的问题是：

> **用户怎么知道自己交代清楚了？Agent 又怎么证明它每一条都做到了？**

---

## 二、核心设计观点

> ### 界面的主角是「这份委托」，不是「聊天记录」。
> ### 对话只是把委托谈清楚的过程。谈成之后，它被委托书吸收掉，消失。

### 这句话最激进的那个推论

> **在这个界面里，不存在「聊天记录」这个东西。**

- 你说的每一句话，要么**变成某一条条款的正文**，要么是对某一条条款的修改
- Agent 说的每一句话，都挂在某一条条款底下
- 谈完之后对话自然消失，因为**它已经变成了委托书本身**

这不是修辞。看截图里第 22 秒那一条：

| | |
|---|---|
| 谈判前 | `二 · 对象 · 三条产品线` |
| 你回答「A、B、C」之后 | `二 · 对象 · 三条产品线：A、B、C` |

**回答不是一条消息，它改写了条款正文。**

---

## 三、Agent 状态

| 状态 | 界面上发生什么 |
|---|---|
| **idle** | 一条底线 + 光标。提示语是「说点什么…」 |
| **drafting** 拟稿 | 回车后它**不开工**，把你那句话拆成条款，一条条浮出来 |
| **negotiating** 谈判 | 一次只问一条。问题在那条底下展开，带两个选项按钮 |
| **ready** 待确认 | 右下角出现「确认并开始」。**没确认之前它一步都不做** |
| **working** 执行 | 条款 ○ → ● → ✓。**只有当前那一条展开**显示它在干什么 |
| **waiting** 需要你 | 某条变朱红并提问，其余不动 |
| **done** 全部兑现 | 每条后面写着兑现结果和耗时，右下角**落一个朱红印章** |
| **unmet** 未兑现 | ⭐ 最重要的一条。写着「写了 2140 字，超出 1500」，旁边一个「只重跑这条」 |
| **error** 中断 | 那条变朱红，标「被你打断」 |

---

## 四、可以真的操作的六件事

| 操作 | 会发生什么 |
|---|---|
| **打字 + Enter** | 有提问时，你的话直接被吸进那一条；没有提问时，用你的话重跑整段 |
| **点选项按钮** | 回答那条提问，同样被吸进条款正文 |
| **点状态行** | 展开 / 收起那一条的兑现过程（只有做过的才有） |
| **点「只重跑这条」** | 只有那一条回到 ●，两秒后变 ✓，**其他四条一动不动** |
| **点「＋ 加一条」** | 把输入框里的字作为一条新约束加进委托 |
| **点「打断」/ Esc** | 当前那条标成「被你打断」，整份文件停下 |

## 五、时间线（26 秒）

| t | 事件 |
|---|---|
| **0.7** | 打字机打入「帮我做一份 Q3 的复盘」 |
| **2.9** | 回车 —— **它不开工** |
| **3.4–4.6** | 五条条款逐条浮现：一 范围 / 二 对象 / 三 数据口径 / 四 材料 / 五 篇幅 |
| **5.1** | 进入谈判 |
| **5.3** | 问「三条产品线具体是哪三条？」 |
| **6.9** | 答「A、B、C」→ **二 的正文变成「三条产品线：A、B、C」** |
| **7.2 / 8.8** | 问口径 → 答「不含税」→ 正文变成「按 GMV（不含税）」 |
| **9.1 / 10.7** | 问材料 → 答「可以」→ 正文变成「周报 4 份（读不到 analytics）」 |
| **11.1** | 全部明确 → 「确认并开始」 |
| **12.4** | 开始兑现 |
| **13.2** | 一 范围 ✓ 0.4s |
| **13.4–15.6** | 四 材料 ● 展开，四份周报逐个打勾，然后收起 |
| **16.3** | 二 对象 ✓ 0.2s |
| **16.7** | ⚠ 三 数据口径：**周报里的 GMV 是含税的，和「不含税」冲突** |
| **18.2** | 你点「改用含税」→ **条款正文被就地改写**成「按含税 GMV」 |
| **20.9** | ✗ **五 篇幅：写了 2140 字，超出 1500** |
| **22.1** | 你点「只重跑这条」 |
| **23.7** | 五 篇幅 ✓ 1460 字 · 1.7s |
| **24.4** | **朱红印章落下** |

> **20.9 到 23.7 这三秒是整个实验存在的理由。**
> 在聊天界面里，「写得短一点」意味着重新生成一整篇，你会丢掉前面所有的确认、口径和材料。
> 在这里，你只重跑那一条。那一条是 1500 字，不是一篇报告。

## 六、视觉语言：「夜里的公文」

深色底上摊着一份亮色的文件。文件是主角，背景退到看不见。

| | |
|---|---|
| **背景** | `#131211` 暖黑。没有纹理、没有渐变、没有光晕 |
| **文件** | 不带卡片、不带圆角、不带阴影。靠**一条左边距竖线**分段，边界就是屏幕边界 |
| **字体** | 条款正文用**衬线**（装了 `Source Serif 4`）—— 一份正式文件该有的字体；编号、状态、耗时用 **Geist Mono** |
| **正文** | **19px / 行高 1.6**。比一般 UI 大，因为这是**要读的东西** |
| **色彩** | 底 `#131211` · 正文 `#ece7dd` · 次级 `#9a938a` · 弱 `#8c857b` · 规则线 `#383430` · **朱红 `#c8623f`（唯一强调色：需要你、未兑现、印章）** · 墨绿 `#7fa07a`（只给已兑现） |
| **边框** | **只有水平规则线**。条款之间不画线，靠留白分开 |
| **圆角** | **0**。这是文件，不是控件 |
| **阴影** | **0** |

### 动效只有四处，每处都有功能含义

| 动作 | 怎么做 | 时长 |
|---|---|---|
| 条款浮现 | 从上方 6px 淡入 | 340ms |
| **打勾** | 对勾是**一笔画出来**的（`stroke-dashoffset`），不是突然出现 | 230ms |
| 展开 | `grid-template-rows: 0fr → 1fr`，高度真的长出来 | 260ms |
| **印章** | 从 1.4 倍缩到 1 倍，带 -14° → -6° 的旋转 | 400ms |

**没有一处是为了好看加的。**

## 七、与 B1–B6 的区别

| | B1–B6 | **A1** |
|---|---|---|
| 研究对象 | Agent 干活的画面 | **用户交给它的那件事** |
| 用户输入 | 一句话，发出去就不管了 | **一份会被逐条谈判、逐条核对的东西** |
| 进度的单位 | 步骤（**Agent 定义的**） | 条款（**你定义的**） |
| 对话的位置 | 是主体，永久保留 | **被吸收进条款，谈完消失** |
| 过程的位置 | 是画面本身 | **是条款底下的一个可展开附件** |
| 「失败」是什么意思 | 出错了 | **你要求的事，有一条没做到** |
| 「再做一次」 | 重新生成 | **只重跑那一条** |

**而且 A1 质疑了一个 B1–B6 全都默认的前提：**
**「用户说一句话，Agent 就该开始干」。** A1 说：不，它应该先问你缺什么。

## 八、实现要点

| 关注点 | 做法 |
|---|---|
| 「对话被吸收」 | 引擎里一张 `ANSWER_INTO` 表：回答某个问题时，条款正文被改写成吸收了这句话的样子 |
| 展开动画 | `grid-template-rows: 0fr/1fr` —— 不写死高度，内容多高都行 |
| 打勾 | 内联 SVG + `stroke-dasharray`，状态一变就重放一次 |
| 印章自动滚底 | 落章时把文件滚到底 —— 收尾那一幕不能被折叠线吃掉 |
| 进度 | 每帧只推进时间；条款的增删改都是离散事件，全程约 30 次重渲染 |

## 九、实现状态

| | 状态 |
|---|---|
| 起草 → 谈判 → 确认 → 兑现 → 未兑现 → 只重跑一条 → 印章 | ✅ |
| 回答被吸收进条款正文 | ✅ |
| 问题 / 兑现过程的展开收起 | ✅ |
| 真打字 / 点选项 / 加一条 / 打断 | ✅ |
| 衬线 + 等宽的字体分工 | ✅ |
| `prefers-reduced-motion` | ✅ |
| 真实 LLM | ❌ 永远不做 |

### 已知取舍

- **条款不能就地编辑**。设计里写了，但这一版只做到「回答会改写条款」，没做「点进去直接改字」。
- **「＋ 加一条」加进去的条款不会被执行**，只标一句「已加入委托」。剧本是固定的。
- **文档比一屏略高**，收尾靠自动滚底。条款再多就得手动滚。
- **移动端只做了「不崩」**。
