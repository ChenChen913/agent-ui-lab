# 008 · 入口与对话 —— 设计笔记

> **这个实验在回答什么**
> 从打开产品到拿到结果，中间这条路长什么样？

## 2026-09 重构：合并了原 010

原来的 008（Baseline）和 010（Home）是两个几乎一样的模板：同样的问候语、
同样的建议卡片、同一个悬浮输入框，010 只是少一个侧栏。合并之后它回答一个
完整的问题——**用户从打开产品到拿到结果，走的是一条什么路**：

    首页态  输入框悬在正中，问候语和几件事，没有别的家具
    ↳ 提交
    对话态  同一个输入框落到底部，过程、工具、图表、正文按它们本来的样子长出来

刻意不放侧栏、不放产物面板——那是 009 的领域。这里只有「一问一答」这条最纯的主干。
原来的侧栏、Canvas 面板与相应节拍已删除。

---

## 为什么重做

第一版的骨架是对的：侧栏、无气泡对话、悬浮输入框、克制的执行状态。
但里面是空的 —— 三条消息、两段文字、一行「正在执行 3 个步骤」。

**那不叫克制，那叫简陋。**

一个能直接排进需求池的东西不是实验；一个**里面什么都没有**的东西也不是实验。
这一版补的是完成度：把一条 Agent 回复做到**丰富到可以截图当参考**的程度。

## 一条回复里现在有什么

| Part | 渲染成什么 |
|---|---|
| 思考 | 可折叠，里面是**真实的三句话**，不是「Thinking…」 |
| 搜索 | **搜索结果卡片**：favicon + 站点 + URL + 标题 + 摘要，一条条排开 |
| 读文件 | 文件条 + **原文预览**（页码 + 正文行） |
| 跑代码 | **代码块 + stdout**，带退出码和耗时 |
| 图表 | **真的画出来的柱状图**（含负值） |
| 正文 | **Markdown**：标题、加粗、表格、引用块、脚注 |
| 产出 | 文件卡片，点开在右侧 **Canvas 里真的渲染一份文档** |

用户消息也不再是一行纯文字，带**附件芯片**（`季度报告.pdf · 4.2 MB`）。

## Markdown 是真的 Markdown

装了 `react-markdown` + `remark-gfm`，不是自己手写的正则。
所以现在支持：标题层级、有序无序列表、**表格**、引用块、行内代码、
**代码块（带语言标签和复制按钮）**、脚注、任务列表、链接。

每一个元素都用自己的 components 映射重写过样式，所以它是**我们的排版**，
不是浏览器默认的 Markdown 样式。

## 过程怎么摆

过程类的 Part（思考 / 搜索 / 读取 / 运行）收在回复顶部的一条**时间线**里，
每一条可以单独展开。图表和正文不折叠 —— 它们是产出，不是过程。

## 已知取舍

- 过程默认是**展开**的，因为这是给人看的样板；真实产品应该默认折叠
- 代码块没有做语法高亮，只有等宽 + 语言标签
- 图表的数值范围是写死的，没有做自适应刻度
- Canvas 里的文档是同一份 Markdown 缩小渲染，不是独立的数据源
- 输入框真打字时回复是固定的两条之一
