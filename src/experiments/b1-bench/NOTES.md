# B1 · The Bench —— 设计笔记

> **这个实验在回答什么**
> Agent 正在干活的时候，界面除了转圈还能是什么样？
>
> 具体说：**「Agent 干活的过程」怎么被看见**。
> 聊天框把过程压成了一行「正在思考…」，而这个实验把过程本身做成了画面的主角。

---

## 一、核心机制：三个动作

整个界面只有三个动作，其余都是装饰。

| 动作 | 含义 | 实现 |
|---|---|---|
| **沉降 Sink** | 一步做完 → 缩小、变灰、往下沉进「轨迹」 | 列表里同一个元素改变形态 + 位置动画 |
| **呼吸 Breathe** | 当前步骤有生命感 | **极慢（2.4s）、极低对比**的明暗循环。**不是转圈** —— 转圈是「我在等」，呼吸是「我在做」 |
| **交接 Handoff** | 新步骤从下方升起，旧的同时让位 | 两个动画重叠 150ms，看起来像接力 |

### 为什么用「最新的在最上面」

hero（当前步骤）的位置**永远不动**，观众的视线不需要追。
完成的步骤往下沉，越往下越小 —— 这就是「沉降」的字面意思，而且**永远不需要滚动**。

### 八个不能违反的节奏原则

1. **0.25 秒内必须有反应。**
2. **每一步时长都不相等**（1.2 / 2.8 / 4.6 / 2.5 / 2.4 秒）—— 等长 = 假。
3. **每次沉降之后留 200ms 空窗** —— 否则像赶场。
4. **全片只允许一次打字机效果。**
5. **进度条必须非线性**：先快 → 卡住 → 再冲。匀速进度条是最假的细节。
6. **中段必须有一次「绕路」。** 这是全片存在的理由。
7. **结尾前必须有 0.9 秒静场。**
8. **总时长 18.5 秒。** 短于 15s 显草率，长于 22s 没人看第二遍。

## 三、三档视觉方案

同一个剧本，三种性格。**共用的骨架不变，分叉的是排版逻辑、字体、动效性格。**

| | **A · 极简黑白** | **B · 暖色纸张** | **C · 冷调玻璃** |
|---|---|---|---|
| 一句话 | 一份正在被写出来的文件 | Agent 在为你写一本书 | 一块会呼吸的仪器面板 |
| 底色 | `#FFFFFF` | `#F7F4EE` | `#0B0E14` |
| 明暗 | 亮 | 亮 | **暗** |
| 强调色 | 黑（红 `#D93A2B` 只用两次） | 赭石 `#B5502E` | 冰青 `#4FD1C5` |
| 字体主角 | 无衬线 Geist | **衬线 Fraunces** | **等宽 Geist Mono** |
| 布局 | 左对齐文档流 + 1px 竖轴 | 双栏书页（左目录 / 右正文） | 居中对称仪表 |
| 圆角 | **0** | 6–10px | 20–24px |
| 玻璃 | 无 | 无 | **有**（+ 冷光斑） |
| 动效性格 | 快、硬、干脆 `cubic-bezier(.2,0,0,1)` | 慢、柔、有重量 | 流畅、有惯性（spring） |
| 沉降动作 | 缩字号 + 位置下移 | 淡出 → 目录里浮现一条 | 沿曲线上浮 + 尺寸弹簧 |
| 总时长建议 | **15.5s**（更紧凑） | **21s**（更从容） | **18.5s**（原版） |
| 练什么 | 排版与层级 | 温度与质感 | 材质与动效 |
| 主要风险 | 太冷、像文档工具 | 太文艺、像老博客 | AI 味、掉帧 |

### 每个方案的一条「生死线」

- **A**：圆角必须是 0，阴影必须没有。**红了就俗。**
- **B**：必须用现代无衬线配件压住衬线，否则会滑向 2010 年的博客模板。
- **C**：**禁止任何渐变背景。** 玻璃只用一层纯色 + 高光边。加渐变立刻变成「AI 味紫蓝模板」。
  另外 `backdrop-filter` 全屏最多同时 3 个（本实现里正好 3 个：结果卡 / 当前面板 / 输入框）。

## 四、怎么调（重要）

**先调时间和节奏，再调视觉。永远不要反过来。**

一个 Agent 界面的好坏，**八成取决于节奏，两成取决于配色**。

### 工具

页面右上角：

| 控件 | 用途 |
|---|---|
| `▶ / ⏸` | 暂停 |
| `↺` | 重播 |
| `0.5× / 1× / 2×` | **最重要** |

### 判断标准

**用 2× 反复看。** 如果节奏对，你会想再看一遍；如果不对，你会想关掉。

这条比任何设计理论都可靠。

### 改节奏

只改 `scenario.ts` 里的 `t` 值。界面不用动。

### 已知取舍

- **进度条用 CSS 动画、计数器用 rAF 直接写 DOM**，所以播放时不会每帧触发 React 重渲染。
  代价：改速度时正在跑的动画会跳一下（可接受）。
- **没有做列表虚拟化。** 这个实验只有 5 步，不需要。
- **移动端只做了「不崩」**，没有重新设计信息层级。如果要认真做移动端，那应该是**另一个实验**。
