# 003 · Terminal —— 设计笔记

> **这个实验在回答什么**
> 终端本身很粗糙，能不能把它设计成一个高级的 Agent Interface？
>
> 这里有两个陷阱：
> **① 陈词滥调** —— 黑底荧光绿、黑客帝国。
> **② 假的** —— 一个聊天界面套上等宽字体。
>
> 所以必须做到：**它真的像终端一样工作，但工艺水平是高端产品的水平。**

---

## 一、核心概念

### 一句话

> **一个 Agent，就是一个跑在终端里的进程。**

### 骨架：终端的两种输出模式 = Agent 的两种状态

这是整个设计的支点：

| 转义 | 含义 | Agent 语义 |
|---|---|---|
| **`\n` 追加** | 已经定论的事 | 写进 scrollback，**永久** |
| **`\r` 原地** | 还没定论的事 | 在状态行 / 进度行上**原地重绘** |

于是界面上只有两个区域：

```
┌─ 顶栏：会话 ─────────────────────────────────────────────┐
│                                                          │
│   ❯ 把过时的依赖升一下，然后跑一遍测试                     │   ← `\n` 已定论
│                                                          │      追加，永久
│   ▾ 查询 npm registry ────────────────────── 2.51s       │
│     typescript  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓  100%        │
│     vite        ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░   62%        │   ← 原地重绘
│     · 37 个依赖 · 3 个过时                                │
│                                                          │
├─ 底栏：Agent 的内部状态 ─────────────────────────────────┤
│  ⠹ 查询 registry   ━━━━━━━━━━━╸────────────  62%  8.42s  │   ← `\r` 永远一行
└──────────────────────────────────────────────────────────┘
```

**用户一眼就能看出「哪些还在变，哪些已经定了」。** 这是聊天界面做不到的区分。

---

## 二、界面结构

| 区域 | 内容 | 性质 |
|---|---|---|
| **顶栏**（34px） | `agent@lab:~/agent-ui-lab` · 步骤计数 · 配色切换 | 会话信息 |
| **主区域** | scrollback：命令、步骤头、日志行、文本进度条、结果面板 | `\n` 追加 |
| **底栏**（30px） | 转圈 + 当前动作 + 细进度条 + 百分比 + 计时 | `\r` 原地 |
| **提示符** | `❯` + 你打的字 + 块状光标，在 scrollback 末尾 | 只在空闲时出现 |

窗口居中、圆角 10px、最大 1100×700，带一层很深的投影 —— 它是一件**摆在桌面上的东西**，不是一个铺满屏幕的页面。

## 三、让终端「高级」的四个决定

### ① 重新设计一套调色板

默认的 ANSI 色（纯红纯绿纯蓝）是终端显廉价的根本原因。所以整个实验用一套**低饱和、高可读**的色板：

| 用途 | 色值 |
|---|---|
| 底 / 面板 | `#0e1012` / `#14171a` |
| 正文 | `#cbc8c0`（暖米白 —— 冷底 + 暖字是高级感的来源） |
| 主强调 | `#d6a45f`（琥珀，不是荧光绿） |
| 成功 / 错误 | `#8fae72` / `#cf7368` |
| 路径 / 工具 | `#7f9fc4` / `#ab86b5` |

三套配色可切换：**琥珀 / 磷绿 / 单色**。

### ② 进度条一格一格跳

**这是整个实验的品味分水岭。**

平滑增长的进度条是网页；**按字符格跳变的进度条才是终端**。

实现上，引擎只在「整格数变化」时才更新状态 —— 所以它天然就是跳的，而且每根进度条只触发约 26 次重渲染。

### ③ 真·文本图形

- **转圈**用的是 braille 点字：`⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`（真正的 CLI spinner）
- **进度条**用 `▓░`，**状态行**用 `━╸─`
- **步骤头**是 `▾ 名称 ──────────── 1.02s` —— 用真字符 `─` 填充并裁切，这是 TUI 的惯用手法
- **结果面板**用 `┌ ─ └` 画出来

没有一个是用 CSS 边框伪造的。

### ④ 动效克制：只有两处

- 光标是**块状**的，1.05s 硬闪（`steps(1,end)`，不是淡入淡出）
- 转圈每 80ms 跳一帧

没有缓动、没有过渡、没有渐变。**终端不动画。**

## 四、可以真的操作的五件事

| 操作 | 会发生什么 |
|---|---|
| **点窗口任意处然后打字** | 真的在提示符后面输入。块状光标跟在你打的字后面 |
| **↑ / ↓** | 命令历史（你先前的输入 + 演示里的那条） |
| **Enter** | 用你的命令重跑整段演示 |
| **输入 `clear`** | 真·清屏 |
| **Esc / Ctrl-C** | **像真终端一样打印 `^C`**，状态行变成「已中断」 |
| **点任意步骤头** | 折叠 / 展开这一步的全部输出（`▾` ↔ `▸`） |

> 演示运行期间**输入框是锁住的** —— 这是真的：命令在跑的时候你打不了字，得先 Ctrl-C。

## 五、时间线

总长 **22.5 秒**。源码：`src/experiments/003-terminal/scenario.ts`

| t | 事件 |
|---|---|
| **0.40–1.90** | 命令以打字机打入提示符 |
| **2.10** | `▾ 读取 package.json` + 进度条「解析依赖树」 |
| **3.60** | `▾ 查询 npm registry` —— **4 条进度条同时跑**，速度各不相同 |
| **6.50** | `! typescript 5.9.3 → 7.0.2   有 breaking change` |
| **7.60** | `▾ 升级依赖` → `$ bun add -D ...` → 安装进度条 |
| **9.70** | `▾ 运行测试` —— **流式输出**（这是终端的高光时刻） |
| **11.40** | `✗ src/lib/prompt.test.ts (9 | 2 failed)` ← **红了** |
| **12.50** | `▾ 定位失败` → 检索调用点 |
| **13.60** | `src/lib/prompt.ts:41  split('``\n``') 丢弃了尾部空行` |
| **14.30** | `▾ 重跑失败的用例` → 两个都绿了 |
| **15.30** | `▾ 运行全部测试` → `128 passed` |
| **19.10** | **结果面板**（TUI 画框） |
| **19.70** | 状态行回到「就绪」，提示符重新出现 |

**节奏曲线：** 单调的绿 → 突然的红 → 定位 → 全绿。终端最有戏剧性的时刻就是**测试挂了**。

## 六、实现要点

| 关注点 | 做法 |
|---|---|
| 进度条 | 引擎按帧算百分比，但**只在整格变化时才 setState** —— 天然跳变，且每根条约 26 次渲染 |
| 转圈 / 计时 | **直接写 DOM**，不进 React（12.5fps × 全程） |
| 自动滚动 | `tail -f` 行为：滚到底，但**用户往上翻之后就不再强制拉回** |
| 折叠 | 每个条目在生成时记录它属于哪个 task，点击步骤头就按 owner 过滤 |
| 中断 | 往 scrollback 里真的追加一行 `^C` |

## 七、三个实验的对比

| | 001 The Bench | 002 One Line | **003 Terminal** |
|---|---|---|---|
| 信息载体 | 多行文字列表 | **一条线的形状** | **日志 + 状态行** |
| 本质问题 | **排版** | **编码** | **信息密度与实时性** |
| 「进行中」怎么表达 | 当前步骤变大 + 呼吸 | 笔尖在动 | **状态行 `\r` 原地重绘** |
| 「已完成」怎么表达 | 沉降成小行 | 留在线上成为纹理 | **`\n` 追加，永久冻结** |
| 空间结构 | 垂直列表 | 水平一维 | **两个区域：历史 / 状态** |
| 色彩 | 黑白 + 2 次红 | **零色彩** | **一整套重新设计的终端色板** |
| 学习重点 | 排版 · 层级 · 节奏 | 信息编码 · 动效 | **文本图形 · 密度 · 真实感** |

**三句话概括：**
> 001 研究「怎么把 Agent 的工作**排**出来」。
> 002 研究「怎么把 Agent 的工作**编码**进去」。
> 003 研究「怎么让 Agent 的工作**看起来真的在发生**」。

### 已知取舍

- **滚动条是浏览器原生的**，只是重新上色了。真正的终端滚动条应该是字符画的 —— 但成本和收益不成比例。
- **窗口是固定 1100×700 居中的**。真终端可以自由缩放；这里没必要。
- **移动端只做了「不崩」**（窗口铺满、去掉圆角）。
