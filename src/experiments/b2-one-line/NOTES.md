# B2 · One Line —— 设计笔记

> **这个实验在回答什么**
> 如果 Agent UI 被压缩到极致，只允许存在一条线，它还能怎么工作？
>
> 进一步说：**Agent 的工作天然是多维的（并行任务、嵌套步骤、进度、错误、产物）。
> 怎么把 N 维编码进 1 维？**

---

## 一、核心概念

### 一句话

> **整个界面，就是一支笔在纸上画一条线。**
> Agent 干活的过程，就是这条线被画出来的过程。

### 二维映射

```
▮━━━━━━━━━━━━━━━━━━━━━━━━━●─────────────────────────────
↑                          ↑                            ↑
用户那句话说完了            笔尖：所有事情都发生在这里      还没走到的地方（很淡）
```

- **已经画出来的部分** = 已经做完的工作
- **笔尖** = Agent 此刻在干什么
- **还没画到的部分** = 未知 / 剩余
- **最后整条线画完** → 纸从这条线**裂开**，露出结果

### 一条物理规律推出全部状态

**线是一根有张力的弦。** 它有张力、有惯性、有阻尼、不可压缩。

所有 Agent 状态都从这一条规律推导出来 —— 不是「给状态配个动画」，而是**同一个物理的不同表现**：

| Agent 语义 | 线的物理行为 |
|---|---|
| 刚收到指令 | **Pluck** 被拨了一下，像琴弦一样震荡衰减 |
| 拆解问题 | **Twist** 一道鼓起沿着线慢慢旅行 |
| 搜索 | **Scan** 两个亮点反向扫描整条轨道 |
| 阅读 N 篇 | **Segment** 线断成 N 段，每段点亮的速度都不一样 |
| 并行做 3 件事 | **Fray（飞白）** 线分成 3 根细丝 |
| 其中一路失败 | **Snap** 一根丝断掉，留一个缺口 |
| 恢复 | **Mend** 缺口接上 |
| 发现矛盾 | **Knot** 线打了一个结，然后**整条线静止 600ms** |
| 换个思路 | **Recoil** 结松开，墨迹往回缩，再从那里重新长出去 |
| 生成结论 | **Ink flow** 线加粗，一道墨流沿着它前进 |
| **完成** | **Split** 线从中间裂开，上下分开，结果从缝里长出来 |

**「完成」不是另起一个面板 —— 是这条线自己打开了。** 约束一路守到最后才兑现。

## 二、界面结构

整个 UI 就是屏幕上的一条横带。**一屏之内没有第二个物体。**

```
┌──────────────────────────────────────────────────────────────────────┐
│      01 / 07                                          暗场    8.4s     │  读数（9.5px）
│                                                                      │
│                                                                      │
│      ▸ 正在核对 · 3 个方向                                            │  字幕（跟着笔尖走）
│      ▮━━━━━━━━━╌╌╌╌═══●─────────────────────────────                │  那条线
│                                                                      │
│      帮我搞清楚这个项目为什么启动这么慢                                 │  用户那句话缩成的墨块
│                                          悬停线上任意处回看 · Esc 中断  │  提示
│                                                                      │
│  B2 · ONE LINE                              23.5s · 13 个状态 · 0 种颜色 │
└──────────────────────────────────────────────────────────────────────┘
```

- 线宽 = 屏幕的 **72%**，上限 1080px，**水平居中**
- 线的上下各留一大片空 —— 那些空白是给「裂开」预留的，闭合时看不见
- B1 是左对齐的**文档**（阅读方向：从上往下）；B2 是居中的**一个物体**（观看方向：盯着它看）

## 三、零色彩

**这个实验一个彩色都不用。**

- 矛盾不靠红，靠**线打了个结**
- 错误不靠红，靠**线崩断了**
- 成功不靠绿，靠**线裂开了**
- 进行中不靠蓝，靠**笔尖在动**

如果这能成立，说明状态语言真的建立在**形状**上，而不是「给状态配个颜色」这种偷懒做法。

整个实验只有两个 CSS 变量决定明暗，所以反转只要改两行：

```css
.ol        { --field: #ffffff; --ink: #111111; }
.ol[data-theme='dark'] { --field: #0b0b0c; --ink: #ededea; }
```

页面右上角有「暗场 / 白场」开关，就是改这个。

## 四、时间线

总长 **23.5 秒**。源码：`src/experiments/b2-one-line/scenario.ts`

| t | 线的行为 | 字幕 |
|---|---|---|
| **0.00** | 白场。一条淡线居中，左端光标呼吸 | `说点什么…` |
| **0.40** | 文字自动打入线上（也能真打字接管） | 你打的字 |
| **1.65** | ⭐ **重音① Pluck**：线被拨动，震荡 500ms | |
| **2.30** | **Twist** 开始 | `拆解问题` |
| **4.20** | **Scan** 开始（两个亮点反向扫） | `搜索资料` |
| **6.65** | 线**断成 4 段** | `阅读 4 篇` |
| **6.70–10.25** | 四段依次点亮，**速度不等**（0.7 / 1.2 / 0.6 / 0.9s） | |
| **10.60** | **Fray 飞白**：分成 3 根细丝 | `并行核对 · 3 个方向` |
| **11.90** | 一根丝**断了** | `一个方向断了` |
| **12.60** | 缺口**接上** | `重连中` |
| **13.30** | 三根**绞合**回一根 | |
| **13.45** | **Knot**：打了一个结 | `两份资料冲突` |
| **14.00** | ⭐ **重音② Freeze**：**全屏彻底静止 600ms**（连呼吸都停） | |
| **14.70** | 结松开，**Recoil**：墨迹向左回缩 | `换个角度重查` |
| **15.55** | 从回缩点**重新长出去** | `重新推导` |
| **17.15** | **Ink flow**：加粗到 3px，墨流开始前进 | `生成结论` |
| **19.60** | 墨流停止。**静场 700ms** | |
| **20.30** | ⭐ **重音③ Split**：线从中间裂开 | |
| **21.00** | 结果在缝中显现 | |
| **23.50** | 完成 | |

### 和 B1 的节奏差异

- B1：**慢 → 快 → 慢**（阅读段落最长）
- B2：**快 → 飞白（最热闹）→ 死寂 → 爆发**，动态范围更大

三个重音的位置也换了：B1 是「第一次沉降 / 绕路 / 静场」，B2 是「**拨动 / 全静止 / 裂开**」。

## 五、可以真的操作的四件事

| 操作 | 会发生什么 |
|---|---|
| **点一下然后打字** | 线就是输入框。你的字写在线上，线自动变成它的下划线。Enter → 你的话缩成左端一个墨块，演示开始 |
| **悬停线上任意处** | 字幕跟到鼠标位置，显示「那一步」是什么 |
| **Esc** | **线松掉**（下垂 + 变淡 + 笔尖停住），900ms 后重新绷紧继续 |
| **点击裂开后的结果** | 线重新合上，回到开头 |

> 「松弛」是只有线才能表达的状态 —— 一个面板没办法「松掉」。

## 六、实现要点

### 只有「节拍」触发 React 重渲染

线是连续运动的，所以每帧都 setState 会毁掉性能。做法：

**引擎每帧只写 CSS 变量，不经过 React。**

```ts
el.style.setProperty('--drawn', L.drawn.toFixed(4))   // 墨迹长度
el.style.setProperty('--open',  L.open.toFixed(4))    // 裂开程度
el.style.setProperty('--shake', shake.toFixed(2)+'px')// 拨动
el.style.setProperty('--s0',   L.strands[0].toFixed(4))
```

React 只在**相位、字幕、步数、结果显现**这些离散事件上重渲染。60fps 下几乎没有 React 开销。

### 全部状态都是 CSS 变量的纯函数

```css
.ol-ink   { width: max(calc(var(--drawn) * 100%), var(--typedw, 0px)); }
.ol-tip   { left: calc(var(--drawn) * 100%); }
.ol-edge-top { top: calc(50% - var(--open) * 110px); }
.ol-strand[data-i='0'] { width: max(0px, calc((var(--s0) - 0.55) * 100%)); }
```

### 中断是怎么实现的

把所有动画的 `t0`（起始时刻）每帧往前推，等于把它们「按住」。900ms 后松开，动画从原来的位置继续。

## 七、最大的风险，和四条防守

**失败模式是「看不懂」。** 一根打结的线、一根飞白的线，如果没有解释，观众只会觉得「这动画挺花哨」。

1. **文字说「在做什么」，形状说「做得怎么样」。** 两者缺一不可。字幕永远在，永远具体。
2. **每个行为第一次出现时，字幕必须正好在解释它。** `并行核对 · 3 个方向` 出现的同时飞白 —— 观众自己就关联上了。
3. **前 3 秒必须毫无歧义。** 打字 → 拨动 → 笔尖开始走，这三步不能有任何花招。
4. **不为炫技加行为。** 13 个状态每一个都对应一个真实的 Agent 语义。

| 13 个状态 + Snap / Mend | ✅ |

| 悬停回看 | ✅ |

| 点击结果重开 | ✅ |
| `prefers-reduced-motion` | ✅ 连续动画停掉，状态仍可读 |
| 真实 Agent 接入 | ❌ 永远不做 |

### 已知取舍

- **字幕跟着笔尖走**是有风险的选择（移动的文字更难读）。目前的处理：超过轨道 68% 时翻到笔尖左侧，避免出界。如果实际看着别扭，改成固定左侧即可（只需删掉 `.ol-tag` 的 `left` 规则）。
- **断裂用「盖一个背景色的缺口」实现**，不是真的把线切成两段。视觉上够用，成本低很多。
- **移动端只做了「不崩」**。要认真做移动端，那应该是另一个实验。
