# B6 · Spatial —— 设计笔记

> **这个实验在回答什么**
> 如果 Agent 的状态不是用列表表达，而是用空间关系表达，会怎么样？

---

## 一、核心概念

### 一句话

> **一片场（The Field）。**
> Agent 处理过的每一样东西，在这片场里有一个位置。

### 空间承担语义

列表里所有的东西都是平等的 —— 只有先后顺序。空间里不是：

| 空间关系 | 含义 |
|---|---|
| **距离** | 相关度。跟当前焦点越远，越不相关 |
| **大小** | 重要性 |
| **亮度 / 模糊** | 注意力。**模糊度就是注意力** |
| **连线** | Agent 建立起来的关联 |
| **深度（z）** | 层次。近了变大变清楚，远了变小变模糊，并且有视差 |
| **移动** | 状态变化 —— 收敛的时候，所有东西向中心塌缩 |

### 最关键的一条：**相机就是注意力**

Agent 的注意力不是高亮某个 DOM 节点 —— 而是**一个会移动、会聚焦的镜头**。
它在场里游走，走到哪里，哪里就清楚；离开，就模糊下去。

**这是列表永远做不到的：列表里所有东西永远一样清楚。**

## 二、整部片子的形状：**展开 → 连接 → 收敛**

```
  ①            ②                        ③
  ●          ○───○                    ○ ○ ○
             │   │                     ○ ○
 一个问题  →  ○───○───○  炸成一片星座 →  ○●○  塌缩成一个答案
             │   │                     ○ ○
             ○───○                    ○ ○ ○
```

1. **展开**（0–8s）：一个问题裂成三个方向（成本 / 召回效果 / 迁移风险）
2. **收集**（8–15s）：每个方向下长出证据节点，场越来越密
3. **矛盾**（15–20s）：两份复现结论对不上 → 两个节点之间拉出一条橙色虚线
4. **查证**（20–24s）：连上一条之前没注意的关系，矛盾解开
5. **收敛**（24–27s）：**所有节点按比例向中心塌缩**，中心长出结论

## 四、视觉语言

| | |
|---|---|
| 底 | `#08090c` 近黑。**没有渐变、没有玻璃、没有任何面板** |
| 网格 | 极淡的坐标网格，**随相机移动产生视差** —— 这让它是「一张有坐标的空间」，不是「星空」 |
| 节点 / 文字 | 暖白 `#e6e4df` |
| 焦点环 | 一圈几乎看不见的同心圆，跟着相机走，**告诉你注意力落在哪** |
| **彩色只有两种** | 冷蓝 `#6ea8d8` = 正在处理 / 新建立的关联；暖橙 `#d8945a` = 冲突。**其余全是灰阶** |

**模糊度是主视觉语言**，不是装饰：
- 离焦点 300 世界单位以内 = 清楚
- 超出之后线性模糊，最多 5.4px
- **再叠加景深模糊**（`abs(depth) × 0.009`）—— 所以前后景也有虚实

## 五、可以真的操作的六件事

| 操作 | 会发生什么 |
|---|---|
| **拖拽** | 平移相机（像看地图），自动脱离「跟随」 |
| **滚轮** | 以鼠标为锚点缩放（0.28× ~ 3.2×） |
| **点一个节点** | 相机飞过去看它，并拉近到 1.15× |
| **悬停一个节点** | 它和它的标签亮起冷蓝，右上角显示它的类型 |
| **点空白** | 进入自由探索模式 —— **焦点变成屏幕中心** |
| **右下角「跟随 Agent」** | 把镜头交还给 Agent 的注意力 |

> 自由探索时，模糊的中心是你自己的视线，不是 Agent 的。**这个区别本身就是设计。**

## 六、时间线（27 秒）

| t | 事件 |
|---|---|
| **0.7** | 场里只有中心一个问题（相机从 1.7× 缓缓拉到 0.9×） |
| **2.6–3.5** | 三个分支依次长出来，各自带一条连线 |
| **4.7–5.6** | 成本这一支的三条证据出现 |
| **6.1–7.3** | 相机逐个飞过去看 |
| **7.9–8.8** | 效果这一支的四条证据 |
| **10.5–11.4** | 风险这一支的三条证据 |
| **12.9** | 新证据 `HNSW vs IVFFlat 复现` 出现 |
| **13.9 / 14.6** | 两个节点变成橙色（冲突） |
| **14.9** | 它们之间拉出一条**橙色虚线** |
| **15.4** | **拉远到 0.62×** —— 让观众看一眼已经长出来的星座 |
| **16.1–17.0** | 三个"发现"节点出现 |
| **18.3** | 连上一条**冷蓝虚线**（之前没注意到的关系） |
| **19.5–19.8** | 两个冲突节点变绿，矛盾解开 |
| **21.0** | **收敛开始**：所有坐标在 2.8 秒内塌缩到 42% |
| **24.0** | 结论从正中央长出来 |

**节奏曲线：** 从一朵花慢慢绽开 → 密到有点乱 → **拉远看一眼全貌** → 解开 → **塌缩**。

## 七、六个实验的完整对照

| | 001 Bench | 002 One Line | 003 Terminal | 004 Chronicle | 005 Desktop | **006 Spatial** |
|---|---|---|---|---|---|---|
| 本质问题 | **排版** | **编码** | **信息密度** | **时间** | **存在感** | **空间关系** |
| 媒介 | 文字列表 | 一条线 | 日志 + 状态行 | 时间轴 | 桌面 + 窗口 | **一片场** |
| 维度 | 1D（垂直） | 1D（水平） | 1D + 实时 | 2D（时间×泳道） | 2D（桌面）× 状态 | **2.5D（x, y, depth）** |
| 「重要」怎么表达 | 字号 | 线的粗细 | 颜色 | 条的长度 | 窗口大小 | **大小 + 清晰度** |
| 「正在做」怎么表达 | 当前项变大 | 笔尖在动 | `\r` 原地重绘 | 播放头 | 本体变形 | **相机聚焦** |
| 并行 | 依次排开 | 飞白 | 进度条 | 泳道 | 多窗口 | **分支节点** |
| 用户在哪 | 列表外 | 线外 | 终端里 | 时间轴上 | 桌面前 | **场里面** |
| 色彩 | 黑白+2红 | **零色彩** | 终端色板 | 冷图纸+朱红 | **环境光** | **灰阶 + 两点彩色** |

**六句话：**
> 001 怎么把工作**排**出来。
> 002 怎么把它**编码**进去。
> 003 怎么让它**看起来真的在发生**。
> 004 它**把时间花在哪了**。
> 005 它**怎么和你共处一室**。
> 006 它**脑子里那张图长什么样**。

## 八、实现要点

| 关注点 | 做法 |
|---|---|
| 每帧只写 DOM | 20 个节点 × 5 次写 + 16 条连线 × 4 个属性 + 3 个网格变量。React 全程只重渲染约 20 次 |
| 视差 | 每个节点有自己的 `persp = 1 + depth × 0.0011`，位置和大小都乘它 —— **所以深度是真的，不是贴图** |
| 焦点环 | 一个 200px 的圆，用 `scale(FR × zoom / 100)` 撑到聚焦半径的真实大小 |
| 网格 | 一个 `repeating-linear-gradient`，只改 `background-position` 和 `background-size` 三个变量 |
| 冲突 | 涟漪动画挂在 `.sp-ripple` 上，**不碰每帧被写的 `.sp-dot` 的 transform** —— 否则动画会覆盖位置 |

### 已知取舍

- **布局是手工极坐标算出来的**，不是力导向。力导向会更"自然"，但**不可复现** —— 每次刷新位置都不一样，没法做设计。
- **节点不能拖动**。真图编辑器可以，这里没必要。
- **收敛是整体缩放**，不是每个节点各自飞向中心。视觉上够用。
- **移动端只做了「不崩」**。
