# 013 · Weight —— 设计笔记

> **这个实验在回答什么**
> 同一块界面，面对「把这段话缩成一句」和「比较 20 个项目」，应该给出同样分量的过程吗？

## 2026-09 追加：分量刻度

分量原来只靠布局表达（一行 → 一条带 → 接管屏幕），这一版让它**看得见**：

- 每个任务带一列刻度，一步一格；轻的任务两小格，重的任务一排密格；
- 重任务的刻度是本模板的橙色，轻的是灰的；
- 空状态改成左对齐排版宣言，附三条演示刻度，一眼看懂「分量」长什么样。

## 观点

> **过程占多大分量，由「用户有多需要知道」决定，不由「Agent 做了多少」决定。**

001 到 006 无条件把过程当主角，007 到 011 无条件把它压成一条或一块。
**分量随任务变这个维度，前面 11 个实验一个都没碰过。**

## 四档分量

| 档 | 什么时候 | 长什么样 |
|---|---|---|
| `none` | 一句话就能完事 | 过程根本不出现，只剩结果 |
| `mini` | 中等任务 | 结果下面一行「3 步」，点开才看得到 |
| `band` | 复杂任务开局 | 一条可展开的带 |
| `full` | 复杂度暴露之后 | **接管主界面**，结果还没出来，过程就是全部 |

## 最要紧的一拍

第三个任务开局只是一条带。跑到第二步时它发现：找到的 8 个里 5 个是 API 框架、
3 个是应用平台 —— **口径根本没定**。这时候过程区**自己长大**了，
并且弹出一句「任务比预想的复杂，过程已展开」。

> **任务的复杂度是逐步暴露的，Agent 一开始也不知道有多复杂。**
> 所以分量应该在执行中长大，而不是一开始就定好。

## 已知取舍

- 四档的切换是写死的时间点，不是真的根据步骤数算出来的
- 「一句话就完事」那一档根本没有 steps 数据，是刻意留空的
- 长大那一拍只有一次，没有做「变小」

## 下次想试什么

- [ ] **变小**：Agent 发现任务比预想的简单，过程区收回去
- [ ] 分量的规则**算出来**而不是写死：步骤数 + 是否有分支 + 是否有外部依赖
- [ ] 用户手动调分量：把某次的过程钉住，以后同类任务都用这个档
