# 011 · Bubble —— 设计笔记

> **这个实验在回答什么**
> 如果 Agent 就长成你最熟悉的那个聊天软件的样子呢？

## 我在探索什么

008 到 010 都在**刻意避开气泡**。它们用的是「现代 AI 产品」那一套：无气泡、大留白、消息就是文字块。

但气泡之所以存在是有原因的：**它让「谁说了什么」变得毫无歧义**，而且十亿人已经会读了。

这个实验反过来问：**把 Agent 塞进这个人人都会用的壳里，会不会反而更好用？**

## 核心观点

> **微信早就有一套完整的词汇，用来描述「异步、会失败、需要等待」的通信。**
> **Agent 正好塞得进去，一条新的界面语言都不用发明。**

| Agent 需要表达的 | 微信里现成的说法 |
|---|---|
| 正在处理 | 标题栏的「对方正在输入…」 |
| 调用了工具 | 居中灰底的系统消息 |
| 产出物 | 会话里的文件卡片 |
| 失败与降级 | 系统消息里直说 |
| 发出的时刻 | 每条消息下面的时间 |
| 说错了想收回 | 撤回 |

这就是这个实验最有意思的发现：**不用发明新范式，老范式已经够了。**

## 样式规格（照微信来）

| | |
|---|---|
| 收到气泡 | `#ffffff`，5px 圆角，朝左的小尖角 |
| 发出气泡 | `#95ec69`，5px 圆角，朝右的小尖角 |
| 头像 | **38×38 圆角方形（4px 圆角，不是圆的）** —— 这是微信最容易被忽略的特征 |
| 昵称 | 气泡上方，12px 灰 |
| 时间 | 气泡下方，11.5px 灰 |
| 会话背景 | `#f5f5f5`（桌面版比手机版浅） |
| 左侧导航条 | `#2e2e2e` 深色，选中态是微信绿 |
| 会话列表 | `#f7f7f7`，选中行 `#e3e3e3` |
| 发送按钮 | `#07c160`，没输入时是灰的 |
| 气泡宽度上限 | 会话区的 68% |

**唯一偏离微信的地方**：微信的时间与昵称是 `#b2b2b2`，在浅灰底上对比度只有 2.3:1，读不清。这里提到 `#8c8c8c`（约 5:1）。颜色没变调，只是亮了。规格出处：微信官方设计规范、以及 Windows 4.x 客户端的界面焕新说明。

## 三栏是怎么来的

微信是手机应用，直接放到 1440px 宽会很难看。所以用的是**微信电脑版**的结构：最左深色导航条（58px）+ 会话列表（252px）+ 会话区。

## 已知取舍

- 昵称在微信里只有群聊才显示。这里两侧都显示，因为这是「一个 Agent 会话」，作者要求能看到是谁说的
- 「撤回」会真的把气泡换成系统消息，但不支持「撤回后重新编辑」
- 「重新生成」只是给原文加个前缀，演示环境没有模型
- 悬停操作条是桌面版的交互，手机上没有（微信是长按弹菜单）

## 下次想试什么

- [ ] **语音条**：微信的语音气泡是一种完全不同的消息形态，Agent 能不能用它
- [ ] **引用回复**：长按某条消息引用它再追问，这样上下文就有出处了
- [ ] **群聊里的多个 Agent**：一个群里放三个 Agent，看它们怎么分工
